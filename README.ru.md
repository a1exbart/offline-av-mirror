# offline-av-mirror

Скачать вирусные базы на машине с интернетом, перенести их на машину без сети и
обновить её там.

*English version: [README.md](README.md).*

Один самодостаточный файл для Windows и Linux: окно для тех, кому нужно окно, и
консольный режим для тех, кому нужен он. Ставить ничего не надо ни на одной из
машин, и на обновляемой машине ничего не остаётся.

Программа разговаривает по протоколу обновлений продуктов **Dr.Web** и
раскладывает файлы так, как их ждут собственные средства этих продуктов. *(Dr.Web
— товарный знак ООО «Доктор Веб». Проект не связан с правообладателем, им не
поддерживается и не одобрен. Нужна ваша действующая лицензия; без неё программа
доступа не даёт.)*

## Зачем

Машинам в изолированных сетях всё равно нужны свежие базы. Обычный ответ —
поднять зеркало на сервере с интернетом; обычная действительность — один
инженер, одна флешка и машина за воздушным зазором. Это короткий путь: скачать
здесь, отвезти, обновить там.

## Что делает

- Скачивает вирусные базы линии обновлений **той машины, которую вы обновляете**
  — продуктов для Linux или для Windows.
- Раскладывает их папкой-зеркалом в вендорском виде, и офлайновая машина
  принимает их своей штатной процедурой обновления из папки.
- По желанию пакует результат в один архив с файлом `.sha256` рядом.
- Сверяет каждый файл с контрольной суммой и размером из индекса зеркала и не
  оставляет ничего, если скачивание оборвалось.

## Чего не делает

Не устанавливает, не обновляет и не настраивает антивирус, не меняет настройки и
не трогает антивирус на машине, где запущена. Она скачивает файлы.

## Что нужно

- **Действующий лицензионный ключ** (`drweb32.key`) обновляемой машины. Зеркало
  пускает клиента по контрольной сумме этого файла; без неё не отдаётся ничего.
- **Файл зоны** этой же машины — он задаёт линию обновлений, а линия принадлежит
  установленной сборке продукта и угадыванию не подлежит:
  - Linux: `/var/opt/drweb.com/drl/bases/zone.ini`
  - Windows: `drwzones.xml` из каталога данных продукта
- Доступ в интернет на машине, где идёт скачивание.

Оба файла находятся сами, если лежат рядом с программой, и любой из них можно
указать кнопкой **Выбрать…** в окне или параметрами `--key` / `--zone` в
консоли. На Linux, если рядом файла зоны нет, берётся зона антивируса этой
машины — и в окне прямо сказано, что источник именно такой. Это удобно, когда
обновляете машину, за которой сидите, но это неверная линия, если базы едут на
другую сборку: смотрите, что написано в окне.

## Как пользоваться

### Окно

Запустите программу без параметров. Выберите линию (Linux или Windows),
проверьте ключ, зону и каталог, отметьте *упаковать в один архив*, если
результат поедет одним файлом, и нажмите **Скачать**.

### Консоль

```console
$ offline-av-mirror download --out /media/usb --archive
offline-av-mirror 1.0.0
Лицензия: № 123456, действует до 23.08.2029
Зона:     unix/…/vdb64
Каталог:  /media/usb
  [1/46] drw11000.vdb
  …
Готово: /media/usb/av-bases-unix-20260920-1530.tar.gz
258 МБ · файлов в наборе: 46
```

| Параметр | Смысл |
| --- | --- |
| `--out КАТАЛОГ` | куда положить результат (по умолчанию — текущая папка) |
| `--key ФАЙЛ` | лицензионный ключ (по умолчанию — `drweb32.key` рядом с программой) |
| `--zone ФАЙЛ` | файл зоны с обновляемой машины |
| `--line unix\|windows` | какую линию искать, если `--zone` не задан |
| `--archive` | упаковать в один архив с файлом `.sha256` |
| `--proxy ХОСТ:ПОРТ` | ходить через HTTP-прокси |

Коды возврата: `0` — готово, `1` — отказ, `2` — ошибка в параметрах, `130` —
прервано.

Язык интерфейса берётся из системы (русский и английский); переопределяется
переменной `OFFLINE_AV_MIRROR_LANG=ru` или `en`.

## Что получается

```
av-bases-unix-20260920-1530/        линия Linux
└── vdb64/
    ├── version2.lst
    └── …

av-bases-windows-20260920-1530/     линия Windows
└── Dr.Web Update Mirror/
    └── …
```

На обновляемой машине:

- **Linux:** `drweb-ctl update --from /путь/к/av-bases-unix-20260920-1530`
- **Windows:** указать продукту в качестве источника обновлений распакованную
  папку `Dr.Web Update Mirror`.

Если просили архив — сначала сверьте его: `sha256sum -c <архив>.sha256`.

### Если машина не принимает базы

Три ответа вендорской утилиты стоит знать заранее — все три встречены на живых
машинах.

- **«Operation is already in progress»** — продукт держит признак начатого
  обновления, и он переживает то обновление, которое его поставило. Сбросить и
  повторить: `drweb-ctl update --Stop`, затем та же команда `update --from`.
- **«Permission denied … Make sure that user drweb has access»** — служба
  работает от своего пользователя и не может прочитать папку внутри чужого
  домашнего каталога. Положите папку туда, где её видно (`/var/tmp`, примонтированный
  носитель), и дайте права: `chmod -R a+rX`.
- **«Virus databases are not loaded»** в ответ `drweb-ctl baseinfo` — это
  состояние движка в памяти, а не дисков. Сразу после обновления это нормально и
  ничего не говорит о только что положенных базах. Правду говорит файл
  `/var/opt/drweb.com/bases/timestamp`: сверьте его до и после.

Строка `Zone DWS skipped` в выводе ожидаема: утилита зеркалит вирусные базы, а не
дополнительную группу веб-рейтингов.

## Ограничения, о которых стоит знать

- Вендор подписывает свои индексы, и **проверить эти подписи программа не может**
  — открытый ключ не опубликован. Целостность держится на sha256 и размере
  каждого файла, взятых из индекса, который получен с адреса из вашего же
  подписанного файла зоны.
- Для линии Windows зеркалится только группа вирусных баз (`vdb`). Компоненты
  самой программы намеренно не скачиваются: обновление продукта — отдельное
  решение, а на аттестованной установке обычно запрещённое.
- Лицензионный ключ читается локально. На зеркало уходит только его контрольная
  сумма, как того требует протокол; сам ключ в результат не копируется и в
  журнал не пишется.

## Сборка из исходников

```console
$ dotnet publish src/OfflineAvMirror -c Release -r linux-x64   # или win-x64
```

Нужен только .NET 10 SDK. Тесты: `dotnet test`.
